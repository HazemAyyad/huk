# Religious content catalog

`catalog.json` is the same bundled content as `F:\flutter_projects\haq_app\assets\religious\catalog.json`, generated by the Flutter checkout's `tool/build_religious_catalog.py`. Scripture is read verbatim from the existing Quran dataset; the original non-Quran source snapshots are retained in that checkout's `tool/religious_sources`.

Public API: `/api/v1/religious/manifest`, `/dataset`, `/categories`, `/content`, `/content/{id}`. The dataset is hashed as exact response bytes. Drafts and hidden categories are omitted. Clients retain their last valid local copy if a download fails validation.

Administration: `/admin/religious-content`, restricted to authenticated `superadmin` users. Changes are stored in `storage/app/religious/catalog.json` using a lock and a complete temporary file before replacement; preserve that directory across deployment and backups. The default bundled file is never overwritten by administration.

Account sync uses the existing religious account and an independent revision/tombstone stream. Deploy `2026_10_15_000001_create_religious_content_sync.php` after the existing religious-account migration. The implementation did not execute either migration on the live/work database.

Full functional scope, sources, visual limitations, and asset prompts are documented in the Flutter checkout's `docs/religious-content-implementation.md`.
