# P15 — Push للمحتوى الديني العام

التطبيق: C:/flutter_projects/haq_app/docs/community-push-implementation.md. التكامل مصدرًا واختبارات فقط، مع تفعيل مؤجل؛ لا حسابات أو مفاتيح أو .env أو قاعدة فعلية أو cron أو إرسال FCM/APNs حي.

## التهيئة

RELIGIOUS_PUSH_ENABLED=false افتراضيًا. التفعيل يحتاج RELIGIOUS_COMMUNITY_ENABLED ومخطط المجتمع، إضافةً إلى RELIGIOUS_PUSH_PROJECT ومعرّف مشروع Firebase وRELIGIOUS_PUSH_CREDENTIALS لمسار service account خاص خارجpublic. الحساب يحتاج صلاحية FCM HTTPv1، ولا نستعمل legacy server key أو مفتاح داخل Flutter. لا ملفات حسابات وهمية أو أسرار فيGit.

مصدر migration `2026_10_27_120000_create_religious_push_outbox.php` ينشئ state للحد الزمني وإيصالات خاصة بالمنشورات. لا نقل بيانات جمعية/موظفين أو إسقاط جدول موجود. تحقّق حالة المهاجرات والنسخ الاحتياطية قبل تنفيذ المصدر لاحقًا على Staging.

الأمر `religious-community:push` مسجّل كل دقيقة مع withoutOverlapping وبوابة الرايات؛ لم ننفذه على خادم. تعالج الدفعة20 إيصالًا افتراضيًا، وtopic ثابت `haq_public_messages_v1` لا يقبل عنوانًا من طلب مستخدم. capability الحالية تضيف `push` كقيمة منطقية دون تسريب مسار الملف أو المشروع أو أسراره.

عند أول تفعيل يثبت activated_at بدل إرسال أرشيف قديم. فقط الرسائل العامة المنشورة/المجدولة الحاضرة وغير المنتهية؛ ليست قصصًا أو تعليقات أو دعوات حسابات. محتوى الإشعار عام ثابت، ومعرّف منشور ومسار messages. لا نص ديني مولّد/مقتبس أو رابط خاص في الإشعار. TTL أقصاه يوم أو نهاية النشر.

## منع التكرار والفشل

publication_id فريد. claim مع قفل ومعاملة قبل HTTP؛ إرسال خارج القفل، ثم تحديث الإيصال بشرط نفسclaim. draft/hidden/expired يعاد فحصها قبل الإرسال. statuses: pending/sending/sent/skipped/failed/uncertain. sent يعني قبول FCM ومعرّف رسالة صحيح فقط، وليس إيصال الهاتف. الرد429/5xx يعاد بانتظار60..3600 ثانية حتى5 محاولات؛ انتهاء مهلة/انقطاع بعد الطلب أو claim قديم أكثر من5 دقائق =uncertain دون إعادة تلقائية. لا exactly-once من FCM. tag/collapse-id ثابت للمنشور يقلل التكرار ولا يثبت عدمه.

فشل بيانات اعتماد قبل محاولةالإرسال يعيد بانتظار؛ فشل/رفض المزود الصريح لا يطبع المفتاح أوالرد الخاص فيlog. مراجعة uncertain تحتاج دليل المزود قبل أي إعادة يدوية؛ لا حذف إيصال أو تصفير/إعادة إرسال آلي لعملية مجهولة. إيقاف الراية يوقف الإرسال المستقبلي، لكنه لا يسحب إشعارًا قبله المزود بالفعل.

## التحقق

خمس اختبارات جديدة مع HTTP محاكى: بوابات التفعيل/الملف، حد الأرشيف والنشر العام مرة واحدة وحمولة بلا محتوى، رد429 وإعادة فحص منشور مخفي، انقطاع/claim مهجور بلا إرسال ثانٍ، ومنشور مجدول ينتظر وقته. نجحت المجموعة94 اختبارًا و1240 تحققًا علىSQLite :memory: فقط؛ Pint وPHP lint للملفات المعدلة نظيفان. اختبار MySQL المتزامن وOAuth الفعلي وFCM/APNs وAndroid/iOS وتوقيع الملفات وcron الفعلي مؤجلة. لا إطلاق معتمد قبل فحصها.

المراجع: [FCM HTTPv1](https://firebase.google.com/docs/cloud-messaging/send/v1-api)، [FCM topics للمعلومات العامة](https://firebase.google.com/docs/cloud-messaging/topic-messaging).
