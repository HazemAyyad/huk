# تطبيق حق: هوية الحساب والصلاحيات وحزم اللغات

## تجهيز النسخة للاختبار على السيرفر — 30 أكتوبر 2026

الأوامر التالية للتنفيذ بعد رفع الكود وأخذ نسخة قاعدة البيانات والملفات. لم تنفذ على قاعدة الجمعية في جلسة التطوير.

```sh
php artisan migrate --path=database/migrations/2026_10_30_120000_create_haq_app_localization.php --force
php artisan migrate --path=database/migrations/2026_10_30_130000_create_app_source_imports.php --force
php artisan db:seed --class=HaqAppAdminSeeder --force
php artisan haq-app:preflight
```

يشترط وجود جداول المستخدمين والحسابات الدينية وSanctum وLaratrust أولًا. `preflight` يقرأ المخطط ويبلغ عن النواقص دون تغيير بيانات، بما فيها جدول `jobs` للطابور. عند غيابه فقط، وبعد مراجعة المخطط، تشغّل migration `0001_01_01_000002_create_jobs_table.php` المحددة. لا تشغّل `DatabaseSeeder` العام: يتضمن سيدر صلاحيات قد يمسح الأدوار الحالية.

السيدر المخصص يسأل عن بريد **جديد** وكلمة مرور مخفية وتأكيدها (14–128 محرفًا). ينشئ هويتي جمعية وديني مربوطتين صراحة ودور `haq-content-admin` بصلاحيات الوحدة فقط. تدخل من التطبيق بالبريد وكلمة المرور اللذين اخترتهما، بمزود الجمعية أو الديني. لا توجد كلمة مرور افتراضية؛ البريد المستخدم سابقًا يرفض دون ترقية أو دمج صامت. إعادة تشغيل السيدر لحسابه السابق تحفظ كلمة المرور والصلاحيات وحالة التعطيل. للتشغيل غير التفاعلي توجد إعدادات `HAQ_BOOTSTRAP_ADMIN_*` الفارغة في `.env.example`؛ لا تضع الأسرار في Git أو سطر أوامر محفوظ.

بعد تجهيز الحساب: اضبط `HAQ_APP_ADMIN_ENABLED=true` ثم حدّث cache الإعدادات بالطريقة المعتمدة للسيرفر. مفتاح Ed25519 مطلوب للنشر فقط؛ دخول اللوحة والتحرير لا يحتاجان مفتاح نشر. المفتاح العام المقابل مطلوب في بناء Flutter لتثبيت الحزم المنشورة.

### مصادر معاني القرآن داخل اللوحة

المسارات الجديدة تحت `admin/languages/{locale}`: `GET/POST sources`، و`GET sources/{id}?surah=...`، و`POST sources/{id}/review`، و`POST sources/selection`. الاستيراد يتطلب `content.edit`، والاعتماد `review`، والاختيار للنشر `publish`؛ جميعها مقيدة بنطاق اللغة.

تختار مصدر QuranEnc من فهرس مؤرخ، ثم تستورد إلى طابور خاص. الطلب يدعم UUID لإعادة المحاولة دون تكرار المهمة، ويعاد استخدام استيراد جارٍ للمصدر نفسه. شغّل العامل منفصلًا عن طلب الويب:

```sh
php artisan queue:work haq_imports --queue=haq-imports --timeout=900 --tries=1
```

الاتصال الافتراضي `haq_imports` من نوع database بمهلة `retry_after=1200`؛ إعداد Supervisor/خدمة الاستضافة مطلوب لاستمراره. فحص الجاهزية لا يدعي أن العامل حي؛ يثبت ذلك استيراد فعلي يصل إلى «جاهز للمراجعة». البيانات الأصلية محفوظة خارج public، والنص والحواشي والإصدار وبصمات الاستجابات لا يعاد تحريرها. المعاينة تقارن بالأصل العربي المحلي؛ مطابقة fil/zh-Hans/ckb تتطلب تأكيد الكتابة/التنويعة صراحة. لا يعتمد المصدر تلقائيًا، وسحب صلاحية الموظف يمنع إتمام المهمة.

اختيار المصدر يعدّل مسودة اللغة فقط، ويصل للمستخدم في الإصدار الموقع التالي بعد النشر. الاسترجاع يحفظ لقطة المصدر السابق. العميل يعرض المعاني والحواشي والإسناد بجانب القرآن العربي، ويعيد تحميل النسخة المثبتة دون إنترنت. النص القرآني المحلي لا يستبدل. حدود الحزمة 8 MiB؛ لا تعني هذه الدفعة تنزيل القرآن المترجم كاملًا أو اكتمال التفاسير والوسائط والـ35 لغة.

بدأ التنفيذ محليًا في 30 أكتوبر 2026 على `codex/haq-multilingual-admin`. لم تنفذ migration على قاعدة الجمعية أو السيرفر. الخطة الرئيسية وسجل Flutter في `C:/flutter_projects/haq_app/docs/`.

## الهوية والصلاحيات

- المكتبة المالكة للأدوار والصلاحيات هي Laratrust الموجودة. لم يجر تشغيل `LaratrustSeeder`؛ إعداده الحالي يحذف جداول الصلاحيات عند التشغيل، ولذلك لا يستخدم لتهيئة هذه الوحدة.
- `AppAccount` يربط `User` و/أو `ReligiousAccount` بمعرّفات صريحة، دون كلمات مرور جديدة. `association_enabled` و`religious_enabled` يحددان نوع الوصول: جمعية فقط، ديني فقط، أو الاثنان. الدور مستقل عن نوع الوصول.
- الحساب العادي لا يصبح مديرًا باختيار نوع الوصول أو إرسال دور في التسجيل. المنح الإداري يتطلب هوية موظف مرتبطة، وسجل منح نشط، وصلاحيات Laratrust الحالية. `superadmin` يتجاوز قيد الصلاحية في Laratrust لكنه لا يتجاوز اشتراط المنح الصريح ونطاق اللغة.
- `admin` أو الموظف يستخدم صلاحياته المباشرة أو الموروثة من أدواره، دون اشتراط superadmin. تغييرات الصلاحية تُقرأ من الجداول في كل طلب لتجنب بقاء صلاحية مخزنة في cache أو رمز قديم.
- `AppAccount` يصدر رمز `app:session` لمدة 30 يومًا مربوطًا ببصمة كلمة مرور مزود الدخول. رمز `app:admin` مستقل لمدة 30 دقيقة ومرتبط بجلسة التطبيق الأم؛ انتهاء الأم أو تغيير كلمة المرور أو سحب المنح يمنع الطلب التالي.
- مزامنة القرآن والمحتوى الحالية تبقى بمالكها `ReligiousAccount` ورمز `quran:sync`، ولا يستطيع هذا الرمز دخول API الإدارة. حساب الجمعية فقط لا يحصل على رمز مزامنة دينية.
- تطابق البريد لا يربط الهويات. `account/link` يتطلب إعادة إثبات الحساب الحالي وبيانات الحساب الآخر. حساب Google الحالي يدعم ID token حديثًا موثقًا؛ الطرف الآخر في هذا الإصدار يحتاج كلمة مرور مفعّلة. الربط يحتفظ بمعرف حساب الجمعية والمنح الموجودة، ويعطل التجميع الديني السابق ويلغي جلسات التطبيق للتجميعين؛ لا ينقل بيانات المفضلة أو يغيّر هوياتها.
- وحدات عمل الجمعية ليست منفذة في Flutter ضمن هذه الدفعة؛ هذا العقد يثبت نوع الوصول دون الادعاء بنقل وحدات الموقع.

| قدرة التطبيق | اسم صلاحية Laratrust |
| --- | --- |
| `admin.enter` | `read_app_admin` |
| `translations.edit` | `update_app_translations` |
| `content.edit` | `update_app_content` |
| `review` | `review_app_content` |
| `publish` | `publish_app_content` |
| `languages.manage` | `update_app_languages` |
| `team.manage` | `update_app_team` |

مدير الفريق لا يعدّل منحه الخاصة ولا يفوض صلاحية أو نطاق لغة أوسع من نطاقه. تعديل منح زميل يضيف صلاحيات Laratrust المطلوبة دون إزالة أي دور أو صلاحية أخرى للجمعية؛ تقليل المنح يمنع استخدام القدرة داخل هذه الوحدة ولو بقيت موروثة من دور آخر.

## العقود المنفذة

جميع المسارات تحت `/api/v2`، مع استمرار مسارات v1 القديمة.

| المسار | الوظيفة |
| --- | --- |
| `POST account/login` | `provider=association/religious` وemail/password؛ يفتح الحساب المجمع المرتبط مسبقًا. |
| `POST account/exchange` | تبادل جلسة دينية موثقة إلى جلسة التطبيق، دون إنشاء حساب جمعية أو ربط بريد. |
| `GET account/session` | المناطق والأدوار والصلاحيات الفعلية والتوجيه الإداري. |
| `POST account/link` | إثبات ملكية الحسابين وربط التجميعين مع إلغاء جلساتهما القديمة. |
| `POST account/logout` | إلغاء الجلسة الأم وسياقات الإدارة التابعة للجهاز. |
| `POST admin/session` | سياق إدارة منفصل محدود العمر. |
| `GET app-content/bootstrap` | اللغات المنشورة فقط؛ لا يعرض المسودات أو الفريق. |
| `GET app-content/releases/{id}` | envelope ثابت: payload الدقيق وSHA-256 وحجمه وتوقيع Ed25519 ومعرف المفتاح. |
| `GET admin/languages` | سجل اللغات الـ35 وتغطية مفاتيح هذه الدفعة والنطاق المسموح. |
| `GET/PUT admin/languages/{locale}/records` | مفاتيح UI أو ترجمات عناصر الكتالوج الحالي؛ بحث وصفحات ومراجعة لمنع فقد التعديل. |
| `POST admin/languages/{locale}/review` | اعتماد نسخة محددة بعد مراجعتها. |
| `POST admin/languages/{locale}/publish` | نشر لقطة ثابتة بعد اعتماد كل المفاتيح المطلوبة؛ يمكن استعادة إصدار سابق داخل إصدار أحدث. |
| `POST admin/languages/{locale}/hide` | إيقاف عرض اللغة للتنزيل الجديد؛ لا يحذف المحتوى المحلي من جهاز المستخدم. |
| `GET admin/languages/{locale}/releases` | آخر 50 إصدارًا للغة لاسترجاع لقطة سليمة. |
| `GET admin/team`, `PATCH admin/team/{id}`, `GET admin/audit` | منح الفريق الحالي وتعديله ضمن صلاحيات المدير وسجل التدقيق مع صفحات. إنشاء أول منح عبر إجراء التهيئة أدناه. |

تحديث ترجمة يبطل اعتمادها. النشر لا يشمل المسودات؛ المفاتيح مطلوبة من registry ثابت. صيغة الرسائل الحالية نص عادي ومتغيرات مسماة `{name}`، وليست ICU كاملة؛ صيغ الجمع المركبة والعملات/التنسيقات الموسعة ما زالت ضمن الاستكمال. تصحيح النص القرآني العربي غير مسموح في محرر المحتوى؛ النص الأصلي محفوظ من مصدره.

## تهيئة عند تجهيز بيئة التشغيل

هذه أوامر تشغيل موثقة، وليست دليلًا أنها نُفذت:

1. نسخة احتياطية وتقييم المخطط الحالي، ثم تشغيل migration الجديدة المحددة `2026_10_30_120000_create_haq_app_localization.php` بعد وجود users وreligious_accounts وSanctum وLaratrust. لا تستخدم migrate عامًا عشوائيًا على قاعدة الجمعية.
2. `php artisan haq-app:initialize` يضيف سجل اللغات ومفاتيح AR/EN كمسودات وصلاحيات الوحدة دون مسح الأدوار أو منح صلاحيات تلقائية.
3. منح حساب قائم صراحة، مثل `php artisan haq-app:initialize --user=STAFF_ID --permissions=admin.enter,translations.edit,content.edit,review,publish,languages.manage,team.manage`، ويمكن تحديد `--religious=RELIGIOUS_ID` و`--association=0` لإدارة دينية فقط و`--locales=en,ar` لنطاق محدد. تُستبدل المعرفات بحسابات جرى التحقق منها؛ الأمر لا ينشئ كلمات مرور. تعارض هويتين مستخدمتين يحتاج الربط المعاد توثيقه داخل التطبيق بدل دمج صامت من CLI.
4. حساب الموظف يحتاج أيضًا أسماء صلاحيات Laratrust من الجدول أعلاه، مباشرة أو عبر دوره. لا يضاف superadmin لمجرد السماح بتحرير ترجمة.
5. تجهيز مفتاح Ed25519 للنشر في مكان سري خارج المستودع، وضبط `HAQ_CONTENT_SIGNING_KEY` و`HAQ_CONTENT_SIGNING_KEY_ID`. السر base64 لمفتاح sodium ذي 64 بايت. لا تُطبع المفاتيح في السجلات ولا ترفع إلى Git. المفتاح العام فقط يُضمّن في Flutter عبر `HAQ_CONTENT_PUBLIC_KEYS` كخريطة معرف→base64؛ يمكن تضمين أكثر من مفتاح للتدوير. لا تُنشأ مفاتيح نشر إنتاجية ضمن الاختبارات.
6. تفعيل `HAQ_APP_ADMIN_ENABLED=true` بعد اكتمال الإعداد. الوضع الافتراضي معطل ويحافظ على التشغيل القديم. غياب sodium أو مفتاح النشر يمنع نشر الحزمة ولا يقبل unsigned fallback.
7. مراجعة النصوص والمصادر من لوحة التطبيق ونشر حزمة تجريبية، ثم اختبار التثبيت والتحديث والرجوع على جهاز قبل الإتاحة العامة.

البناء الحالي للحزم الصغيرة متزامن داخل معاملة قصيرة وميزانية 8 MiB؛ لم ينفذ بعد طابور بناء للوسائط والحزم الكبيرة. الخطة تشترط نقله لمهام عند إضافة تلك الموارد. Range غير مضمون مع JSON response؛ Flutter يستأنف عندما يعيد السيرفر 206 سليمًا، ويبدأ من الصفر بأمان عندما يعيد 200.

## حدود هذه الدفعة

الواجهة الجديدة تدير ترجمات عناصر الكتالوج الحالي، ولا تنفذ بعد إنشاء أنواع محتوى جديدة، أو إدارة مصادر التفسير/القراء، أو رفع الوسائط، أو استيراد/تصدير دفعات. إصدارات UI الأولية بالعربية والإنجليزية تغطي التنقل وشاشات اللغة والحساب والإدارة فقط؛ لا تُحسب كل شاشات التطبيق مترجمة. بقية اللغات والمراجعة البشرية والمصادر والتحقق من الخطوط والأجهزة والنشر ما زالت مطلوبة.

المحتوى العربي المضمّن في Flutter لم يحذف أو يستبدل بتحميل إلزامي. تعديلات عربية منشورة لعناصر الكتالوج توضع فوق الأصل محليًا بمعرفاته الثابتة بعد التحقق من الحزمة، مع حماية نص القرآن؛ أي فشل يبقي الأصل أو النسخة السليمة السابقة.
